Q: 假设你非常精通 Claude code 的使用和原理, 我使用 claude code 一段时间后, 发现它能帮我做很多事情, 但是我却不清楚它使用了哪些 prrompt 与 LLM 进行沟通, 有哪里可以看到每次请求时的具体 prompt 吗? 我启动 claude 时带上了 --debug --debug-file ./claude_debug.log 参数, 在 --debug-file 指定的文件中也没有看到相关内容, 有什么办法可以看到吗

你发现在 `--debug-file` 指定的日志文件中没有看到具体的 Prompt, 这是因为 Claude Code 的 Debug 日志主要用于记录应用级别的执行状态(如环境诊断、网络错误、文件读写错误等), 而完整的 Prompt(往往包含大量的上下文、文件内容、工具定义)由于体积过大, 并没有被直接设计打印在 Debug 日志中.

不过, 你有以下几种非常有效的方法可以查看 Claude Code 具体的 Prompt 以及它与 LLM 的详细交互过程:

### 方法一: 查看本地自动保存的 `JSONL` 通话记录(最官方推荐)

Claude Code 实际上会自动把所有的对话上下文、System Prompt、工具调用(Tool calls)和返回结果完整地保存在本地的 `.jsonl` 文件中. 你可以直接去读取这些文件.

1. 查找路径:

   * Mac/Linux: `~/.claude/projects/<项目哈希值>/<session-id>.jsonl`

   * Windows: `%USERPROFILE%\.claude\projects\<项目哈希值>\<session-id>.jsonl`

2. 查看内容:

   你可以直接用文本编辑器或 `jq` 打开这些文件, 里面以结构化的 JSON 记录了每一次请求发送的 `messages` 数组和各种上下文(包括具体的 Tool Input 和 Output).

3. 使用可视化工具(可选):

   因为纯看 JSONL 比较费劲, 目前 GitHub 社区已经有开发者做了一些专门解析这些日志的工具, 比如:

   * [claude-code-log](https://github.com/daaain/claude-code-log): 可以通过命令 `uvx claude-code-log@latest --open-browser` 直接把你本地所有的日志转换为漂亮易读的 HTML 网页进行查看.

### 方法二: 在终端内开启 `--verbose` 或按 `Ctrl+O`(实时查看)

如果你只是想在运行过程中知道 Claude Code 此时到底塞了什么上下文、使用了什么工具、以及它内部的"思考过程(Thinking)":

* 快捷键 `Ctrl+O`: 在 Claude Code 交互界面中随时按下 `Ctrl+O` 可以开启"详细日志(Verbose output / Transcript viewer)"模式. 它会将底层的多步 Tool 链、隐藏的提示及模型的实时推理想法(通常是灰色的斜体字)全部在屏幕上打印出来.

* 启动参数: 或者你在启动时带上 `claude --verbose`.

### 方法三: 通过本地代理拦截 API 请求(硬核, 抓取最原始的 HTTP Request Payload)

如果你想看到最纯粹、最原始的传给 Anthropic API 的 JSON Body(比如想确切看到 System Prompt 被拼成了什么样子、Tool Schema 是怎么下发的), 你可以用一个本地代理(如 LiteLLM Proxy 或 Mitmproxy)来拦截请求.

1. 安装 LiteLLM Proxy:

   ```bash
   pip install 'litellm[proxy]'
   ```

2. 启动代理监听本地端口(如 4000):

   ```bash
   litellm --detailed_debug
   ```

3. 告诉 Claude Code 将 API 请求打向本地代理:

   ```bash
   export ANTHROPIC_BASE_URL=http://localhost:4000
   claude
   ```

采用这种方法, 你会在 LiteLLM 的终端里看到 Claude Code 每一次请求发出时, 携带的完完整整的 `system`、`messages` 和 `tools` 字段内容. 许多研究者就是用这种方式发现 Claude Code 在底层是如何通过各种小 Prompt 和 Sub-agents 来动态拼装上下文的.

### 补充: 想看它内置的默认 System Prompt?

Claude Code 的 System Prompt 是根据你所处的环境、使用的工具(Bash、Edit 等)动态拼装的(通过 JavaScript 动态合成). 如果你纯粹好奇它在底层使用了哪些黑魔法提示词, 可以直接去查看社区维护的 GitHub 仓库 [Piebald-AI/claude-code-system-prompts](https://github.com/Piebald-AI/claude-code-system-prompts). 这个仓库实时解包并整理了最新版本 Claude Code 所使用的约 40 多个内部系统提示词(System Reminders).

Q: 我现在使用 ollama 启动一个本地的模型服务, 然后设置如下环境变量
```
export ANTHROPIC_AUTH_TOKEN=ollama
export ANTHROPIC_BASE_URL=http://127.0.0.1:11434
export ANTHROPIC_MODEL=gemma4:31b-custom
```
最后启动 claude code
```
claude --verbose --debug --debug-file ./claude_debug.log --name taichu-studio-ai
```
对于方法三: 通过本地代理拦截 API 请求, 我应该如何根据我现有的流程操作

针对你目前使用 Ollama 本地模型服务的流程, 如果想要通过本地代理拦截并查看 Claude Code 发送的最原始的 Prompt(JSON Payload), 你需要引入一个 "中间人(Man-in-the-Middle)".

现有的请求流是: `Claude Code` -> `http://127.0.0.1:11434` (Ollama)

加入代理后的请求流是: `Claude Code` -> `http://127.0.0.1:8080` (代理服务: 负责打印日志) -> `http://127.0.0.1:11434` (Ollama)

这里为你提供两种最直观的操作方案.

---

### 方案一: 使用 `mitmdump`(轻量级、专业的抓包方案)

`mitmproxy` 是最专业的 HTTP 拦截工具, 它的命令行版本 `mitmdump` 非常适合这种场景.

1. 安装 mitmproxy

```bash
pip install mitmproxy
```

2. 创建一个简易拦截脚本

在你当前的目录下新建一个名为 `log_prompt.py` 的文件, 写入以下 Python 代码. 这段代码的作用是: 拦截请求并把发向 Ollama 的 JSON Body(里面包含所有 Prompt 和工具定义)漂亮地打印在终端上.

```python
# log_prompt.py
from mitmproxy import http
import json

def request(flow: http.HTTPFlow):
    # 只拦截包含请求体的 POST 请求
    if flow.request.method == "POST":
        print("\n" + "="*50)
        print(f"🚀 [拦截到 API 请求] {flow.request.url}")
        try:
            # 尝试解析并格式化打印 JSON
            body = flow.request.json()
            print(json.dumps(body, indent=2, ensure_ascii=False))
        except:
            # 如果不是标准 JSON, 打印原始文本
            print(flow.request.get_text())
        print("="*50 + "\n")
```

3. 启动 mitmdump 反向代理

开一个新的终端窗口, 运行以下命令:

```bash
# 启动代理监听 8080 端口, 并将流量转发给本地的 Ollama (11434)
mitmdump --mode reverse:http://127.0.0.1:11434 -p 8080 -s log_prompt.py
```

4. 修改你的环境变量并启动 Claude Code

回到你启动 Claude Code 的终端, 将 `ANTHROPIC_BASE_URL` 的端口指向代理服务的 8080 端口:

```bash
export ANTHROPIC_AUTH_TOKEN=ollama
export ANTHROPIC_BASE_URL=http://127.0.0.1:8080  # 注意: 这里改成了 8080
export ANTHROPIC_MODEL=gemma4:31b-custom

# 启动 claude
claude --verbose --debug --debug-file ./claude_debug.log --name taichu-studio-ai
```

现在, 你在 Claude Code 中输入任何内容时, 你都能在运行 `mitmdump` 的那个终端里, 看到完完整整、格式化好的 JSON Prompt(包含 `system` 提示词、`messages` 历史记录和 `tools` 模式)!

---

### 方案二: 使用纯 Python 脚本(无需额外安装复杂的抓包软件)

如果你不想安装 `mitmproxy`, 可以直接写一个仅几十行的 Python (Flask) 反向代理脚本.

1. 安装依赖

```bash
pip install flask requests
```

2. 创建并运行 `proxy.py`

```python
# proxy.py
from flask import Flask, request
import requests, json

app = Flask(__name__)
OLLAMA_URL = "http://127.0.0.1:11434"

@app.route('/', defaults={'path': ''}, methods=['GET', 'POST', 'PUT', 'DELETE'])
@app.route('/<path:path>', methods=['GET', 'POST', 'PUT', 'DELETE'])
def proxy(path):
    # 1. 拦截并打印 Prompt
    print(f"\n\033[92m=== Intercepted Request to /{path} ===\033[0m")
    if request.is_json:
        print(json.dumps(request.json, indent=2, ensure_ascii=False))
    else:
        print(request.get_data(as_text=True))
    print("\033[92m=====================================\033[0m\n")

    # 2. 转发给真实的 Ollama
    resp = requests.request(
        method=request.method,
        url=f"{OLLAMA_URL}/{path}",
        headers={key: value for (key, value) in request.headers if key != 'Host'},
        data=request.get_data(),
        cookies=request.cookies,
        allow_redirects=False
    )

    return (resp.content, resp.status_code, resp.headers.items())

if __name__ == '__main__':
    app.run(port=8080)
```

运行这个脚本(`python proxy.py`), 然后同样将你的 `ANTHROPIC_BASE_URL` 设置为 `http://127.0.0.1:8080` 再启动 Claude Code 即可.

### ⚠️ 重要提醒(关于 Claude Code 与 Ollama 的兼容性)

通过上面的方法, 你一定能成功抓取并看到 Claude Code 生成的 Prompt. 但在你的现有流程中, 极大概率会遇到 API 报错, 原因如下:

Claude Code 底层使用的是 Anthropic API 格式(它会向 `/v1/messages` 端点发送符合 Anthropic 规范的 JSON).
而 Ollama 原生只支持 Ollama 自身格式(`/api/chat`)和 OpenAI 兼容格式(`/v1/chat/completions`).

如果你只是用一个透明代理直接把 Anthropic 格式的请求原封不动扔给 Ollama, Ollama 是无法理解并会返回 404 或报错的.

如果你确实遇到了报错, 你需要的不只是一个"代理拦截器", 而是一个"API 翻译器":
你可以使用 [LiteLLM](https://docs.litellm.ai/docs/proxy/quick_start), 它既能在终端帮你打印出底层请求, 又能把 Anthropic 的请求即时翻译成 Ollama 认识的格式.

启动 LiteLLM 的命令类似这样(启动后修改 `ANTHROPIC_BASE_URL` 指向 LiteLLM 即可):

```bash
# 启动 LiteLLM, 开启详细 Debug 模式(这将在终端打印出所有的请求与响应内容)
litellm --model ollama/gemma4:31b-custom --detailed_debug
```

完全可以分步骤执行. 事实上, 这是最标准、最易于调试的架构.

在这个架构中, LiteLLM 不仅仅是一个抓包代理, 它更是一个"翻译官". 因为 Claude Code 只能说"Anthropic 语言"(发送 `/v1/messages` 请求), 而 Ollama 只能听懂"Ollama 语言"或"OpenAI 语言". LiteLLM 负责在中间进行格式转换, 同时把双边的对话内容打印给你看.

以下是详细的分步执行过程和原理拆解:

### 第一步: 启动 Ollama 模型服务 (终端 1)

首先, 确保你的 Ollama 正常运行, 并加载了你指定的模型.

```bash

ollama serve

# (可选)你可以另开一个窗口确认模型已经可用
# ollama run gemma4:31b-custom
```

这一步发生了什么: Ollama 在 `11434` 端口启动了一个 HTTP Server, 等待接收 OpenAI 格式或 Ollama 原生格式的推理请求.

---

### 第二步: 启动 LiteLLM 代理与翻译服务 (终端 2)

接下来, 我们需要安装并启动 LiteLLM, 让它监听 `8080` 端口, 并将请求转发(且翻译)给 `11434` 端口.

1. 确保安装了 LiteLLM 代理版:

   ```bash
   pip install 'litellm[proxy]'
   ```

2. 启动 LiteLLM 代理服务:

   使用以下命令启动, 明确指定模型前缀为 `ollama/`(这告诉 LiteLLM 目标是 Ollama), 并指定目标 API 地址和监听端口:

   ```bash
   litellm \
     --model ollama/gemma4:31b-custom \
     --api_base http://127.0.0.1:11434 \
     --port 8080 \
     --detailed_debug
   ```

   参数解释:

   * `--model ollama/...`: 告诉 LiteLLM 下游使用的是什么后端的什么模型.

   * `--api_base`: 指定本地 Ollama 的实际地址.

   * `--port 8080`: 让 LiteLLM 监听 8080 端口(替代默认的 4000).

   * `--detailed_debug`: 最核心的参数, 它会在终端打印出极为详细的 JSON 请求体和响应体.

这一步发生了什么: LiteLLM 现在在 `8080` 端口待命.

---

### 第三步: 配置并启动 Claude Code (终端 3)

现在, 我们要"欺骗" Claude Code, 让它以为它在和 Anthropic 官方的服务器通信, 实际上我们将流量导向了刚才建立的 LiteLLM 代理(8080 端口).

```bash
# 1. 设置 Claude Code 发送请求的目标地址为 LiteLLM 代理
export ANTHROPIC_BASE_URL=http://127.0.0.1:8080

# 2. 随便设置一个 API KEY(LiteLLM 默认需要过一下校验, 内容不重要, 除非你在 LiteLLM 中开启了严格鉴权)
export ANTHROPIC_API_KEY=sk-ollama-local-test

# 3. 启动 Claude Code
claude --verbose --name taichu-studio-ai
```

### 🔍 内部详细的数据流向与转换过程(你会在终端 2 中看到的现象)

当你在 Claude Code 中输入一个指令(例如: "列出当前目录下的文件")时, 整个请求链条是这样的:

#### 1. Claude Code 内部打包 (发送方)

Claude Code 收集当前的操作系统信息、内置工具(Bash、读文件等)的 JSON Schema, 以及你的输入, 按照 Anthropic API 的规范组装成一个巨大的 JSON, 并通过 POST 请求发向 `http://127.0.0.1:8080/v1/messages`.

#### 2. LiteLLM 拦截与翻译 (中间层 - 终端 2 打印内容)

LiteLLM 收到了这个请求. 因为你加了 `--detailed_debug`, 你会在此刻的 终端 2 中看到类似这样的输出(这就是你梦寐以求想看到的 具体 Prompt):

```json
// 这是 LiteLLM 打印出的, Claude Code 原始发出的 Anthropic 格式 Payload
{
  "model": "claude-3-5-sonnet-20241022",
  "system": "You are a senior developer... (这里是超级长的系统提示词)",
  "messages": [
    {"role": "user", "content": "列出当前目录下的文件"}
  ],
  "tools": [
    {
      "name": "Bash",
      "description": "Run bash commands...",
      "input_schema": {...}
    }
  ]
}
```

随后, LiteLLM 瞬间进行格式翻译, 把上述 Anthropic 格式转换为兼容 Ollama 的 OpenAI 格式(将 `system` 塞入 messages 的 role 中, 将 `tools` 转换为 OpenAI 的函数调用格式), 并将其发送给 `http://127.0.0.1:11434/v1/chat/completions`.

#### 3. Ollama 推理与响应 (接收方)

Ollama 接收到 OpenAI 格式的请求, `gemma4:31b-custom` 模型开始推理, 决定需要调用 `Bash` 工具. Ollama 返回结果.

#### 4. LiteLLM 逆向翻译 (中间层返回)

LiteLLM 收到 Ollama 的返回, 再次进行逆向翻译, 把 OpenAI 的响应格式转回 Anthropic 的响应格式, 返回给 `127.0.0.1:8080` 的请求方(Claude Code).

#### 5. Claude Code 执行动作

Claude Code 收到响应, 解析出模型想要调用 `Bash` 命令执行 `ls`, 并在你的本机实际执行该命令, 接着将执行结果打包进行下一轮循环.

### 总结

通过这三步分离运行, 终端 2 (LiteLLM) 彻底变成了你的 "X光机". 你不仅解决了 Claude Code 无法直接与 Ollama 工具调用兼容的问题, 还能事无巨细地监控每一次 Claude Code 究竟向大模型下达了怎样精妙的系统级指令(System Prompt)和工具定义.
